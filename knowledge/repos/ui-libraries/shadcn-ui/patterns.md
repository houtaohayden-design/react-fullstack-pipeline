# shadcn/ui — Patterns

## Styling Approach

### Tailwind CSS v4 Exclusively
- No CSS-in-JS, no CSS modules, no separate CSS files
- All styling is inline via Tailwind utility classes in `className`
- Uses Tailwind v4 features: `@container`, `data-[state]` selectors, CSS custom properties, `--spacing()`, `has-`, `in-`, `group-`, `peer-` variants
- Dark mode via Tailwind `dark:` prefix throughout

### CVA (class-variance-authority) for Component Variants
- Used in: Button, Badge, Toggle, ToggleGroup, SidebarMenuButton
- Pattern:
```typescript
const componentVariants = cva(
  "base classes shared across all variants",
  {
    variants: {
      variant: { /* variant classes */ },
      size: { /* size classes */ }
    },
    defaultVariants: { variant: "default", size: "default" }
  }
)
```

### cn() Utility = tailwind-merge + clsx
```typescript
import { clsx } from "clsx"
import { twMerge } from "tailwind-merge"
export function cn(...inputs: ClassValue[]) { return twMerge(clsx(inputs)) }
```
- Used on every component for className merging
- `twMerge` resolves conflicting Tailwind classes (e.g., `px-4 px-6` -> `px-6`)
- Pattern: `className={cn("base-classes", className)}` where `className` comes from props

### Theme Token System
CSS custom properties define the design system:
- `--primary`, `--primary-foreground` — brand color
- `--background`, `--foreground` — page theme
- `--card`, `--card-foreground` — card surface
- `--muted`, `--muted-foreground` — secondary text
- `--accent`, `--accent-foreground` — hover/focus states
- `--destructive`, `--destructive-foreground` — error states
- `--border`, `--input`, `--ring` — borders and focus rings
- `--radius` — border radius
- `--sidebar-*` — sidebar-specific tokens

Classes reference these as `bg-primary`, `text-primary-foreground`, etc.

## The Copy Model (Not an npm Package)

### Architecture
- Components are **copied into your project** via `npx shadcn add`
- They live at `@/components/ui/` (configurable via `components.json`)
- **You own the source code** — customize directly without fighting node_modules
- No version-lock: you decide when to update by re-running `npx shadcn add`
- Dependencies (Radix, CVA, etc.) are installed as regular npm deps when needed

### Project Structure
```
src/
  components/
    ui/
      button.tsx
      card.tsx
      dialog.tsx
      ...
components.json      # shadcn config (generated by init)
```

## Common Component Patterns

### 1. `data-slot` Attribute
Every component has a `data-slot` attribute for CSS targeting:
```tsx
<button data-slot="button" ... />
<div data-slot="card-header" ... />
```
This replaces the older `data-slot` approach and allows:
- `[data-slot=button]:hover:-` in Tailwind
- Consistent selectors in devtools

### 2. Radix Primitive Passthrough
Components built on Radix primitives follow this pattern:
```tsx
import { Select as SelectPrimitive } from "radix-ui"

function Select({ ...props }: React.ComponentProps<typeof SelectPrimitive.Root>) {
  return <SelectPrimitive.Root data-slot="select" {...props} />
}
```
- Wrap Radix primitives with styled versions
- Add `data-slot` for CSS targeting
- Forward all props via spread
- Export compound components from single file

### 3. asChild (Polymorphic Components)
Uses Radix `Slot` for the `asChild` pattern:
```tsx
import { Slot } from "radix-ui"

function Button({ asChild = false, ...props }) {
  const Comp = asChild ? Slot.Root : "button"
  return <Comp data-slot="button" {...props} />
}
```
- Allows: `<Button asChild><Link href="/">Home</Link></Button>`
- The Button's styles merge onto the child via Slot
- Available on: Button, Badge, BreadcrumbLink, SidebarMenuButton, SidebarGroupLabel

### 4. Compound Component Pattern
Large components are split into sub-parts, all exported from one file:
```tsx
// card.tsx
export { Card, CardHeader, CardTitle, CardDescription, CardAction, CardContent, CardFooter }
```
- No default exports — only named exports
- Each sub-part is a simple div with Tailwind styling
- Inter-component relationships via composition, not props

### 5. Context-based State Sharing
Complex components use React Context:
- **Sidebar:** `useSidebar()` hook accessing `SidebarContext`
- **Carousel:** `useCarousel()` hook accessing `CarouselContext`
- **Chart:** `useChart()` hook accessing `ChartContext`
- **Form:** `useFormField()` hook accessing `FormFieldContext` + `FormItemContext`

### 6. Form Integration Pattern
```tsx
// react-hook-form + zod integration
const form = useForm({ resolver: zodResolver(schema) })

<Form {...form}>
  <FormField control={form.control} name="email" render={({ field }) => (
    <FormItem>
      <FormLabel>Email</FormLabel>
      <FormControl><Input {...field} /></FormControl>
      <FormDescription>Your email address.</FormDescription>
      <FormMessage />  {/* Auto-shows validation errors */}
    </FormItem>
  )} />
</Form>
```

### 7. Lucide-react Icons
All icons come from `lucide-react`:
```tsx
import { ChevronDownIcon, CheckIcon, XIcon } from "lucide-react"
```
- Icons have `size-4` default sizing via `[&_svg:not([class*='size-'])]:size-4`
- Icons shrink with `[&_svg]:shrink-0`
- Icons are pointer-events:none with `[&_svg]:pointer-events-none`

### 8. Animation System (Tailwind v4)
```css
/* Used across components */
animate-in / animate-out
fade-in-0 / fade-out-0
zoom-in-95 / zoom-out-95
slide-in-from-top-2 / slide-in-from-bottom-2
accordion-down / accordion-up
```
- No framer-motion dependency
- CSS-only animations via Tailwind keyframes
- Triggered by Radix `data-state` attributes: `data-[state=open]`, `data-[state=closed]`

### 9. Disabled and Invalid States
Consistent patterns across all interactive components:
```
disabled:pointer-events-none disabled:opacity-50
aria-invalid:border-destructive aria-invalid:ring-destructive/20
dark:aria-invalid:ring-destructive/40
```

### 10. Responsive Design
- Tailwind breakpoints directly in className: `sm:`, `md:`, `lg:`, `xl:`
- Mobile-first: base styles are mobile, breakpoints add desktop
- Example: Sidebar renders as Sheet on mobile, fixed sidebar on desktop

### 11. Focus Ring System
```
focus-visible:border-ring focus-visible:ring-[3px] focus-visible:ring-ring/50
```
- Uses `focus-visible` (not `focus`) for keyboard-only focus indicators
- 3px ring with 50% opacity ring color
- Border changes to `border-ring` on focus

### 12. Data-attribute State Selectors
Tailwind v4 supports `data-[state]` selectors natively:
```
data-[state=open]:animate-in
data-[state=closed]:animate-out
data-[active=true]:font-medium
data-[disabled=true]:opacity-50
data-[selected=true]:bg-accent
```
- Replaces earlier `group-data-[state]` patterns with cleaner syntax

### 13. Portals for Overlays
All overlay components use portals:
```tsx
// Dialog, DropdownMenu, Select, Popover, HoverCard, etc.
return (
  <Primitive.Portal>
    <Primitive.Content ...>{children}</Primitive.Content>
  </Primitive.Portal>
)
```
- DialogContent wraps Portal + Overlay internally
- DropdownMenuContent wraps Portal + Content

## Compatibility Notes

### With react-bits
- Fully compatible — use react-bits for page-level animations, shadcn for styled UI
- react-bits provides CSS/JS animations, shadcn provides Tailwind-styled components

### With Tailwind CSS
- **Required** dependency; shadcn is built entirely on Tailwind
- v4 recommended, but v3 configurations exist

### With React Versions
- React 18+ required (uses `useId`, concurrent features)
- Server Components compatible where marked with `"use client"`

### Custom Themes
- Override CSS custom properties in your global CSS to create custom themes
- Each component extends the base token system — change tokens, change everything
- Multiple themes via CSS classes or data attributes

## Interesting Architecture Decisions

1. **All Radix imports consolidated:** Uses `radix-ui` package (NOT individual `@radix-ui/react-dialog` etc.) — this is a v4 change for bundle size
2. **No default exports:** Everything is named export for tree-shaking
3. **displayName is implicit:** No explicit `Component.displayName = "Component"` — relies on function name inference
4. **forwardRef is implicit:** No explicit `React.forwardRef` — functional components receive ref via spread props
5. **CSS cascade via data attributes:** `data-slot` and `data-variant` enable sibling/descendant selectors without class name conflicts
6. **Cookie-based state:** Sidebar collapsible state persists via cookies (7-day max-age)
7. **Embla carousel:** Not a wrapper around a headless library, but a full integration with keyboard navigation
8. **Vaul drawer:** Not based on Radix Dialog — separate library for touch-friendly bottom sheets
