# react-bits -- Patterns & Best Practices

## Architecture & Distribution Model

react-bits uses a **copy-paste component** distribution model (like shadcn/ui), not a traditional npm package. Each component is a self-contained `.jsx` or `.tsx` file you add directly to your project. This means:

- **No tree-shaking needed** -- you only include what you use
- **Full source control** -- edit component internals freely
- **Zero version conflicts** -- components are your code, not a dependency
- **Per-component dependencies** -- install only what your chosen components need

The library itself (https://github.com/DavidHDev/react-bits) is a documentation site built with Vite + React 19 that showcases all components. The `src/content/` directory contains the canonical component source files.

## Variant System

Every component supports 4 technology variants:

```
ComponentName/
  (files are named internally, generated by jsrepo)
  JS-CSS  -- JavaScript + vanilla CSS
  JS-TW   -- JavaScript + Tailwind CSS
  TS-CSS  -- TypeScript + vanilla CSS
  TS-TW   -- TypeScript + Tailwind CSS
```

Pick the variant matching your project's stack. The Tailwind variants use `clsx` for conditional class merging.

## How to Combine Animations

### Pattern 1: Text Animation on a Background

```jsx
import Aurora from './components/Aurora';
import BlurText from './components/BlurText';

function Hero() {
  return (
    <div className="relative h-screen">
      <Aurora className="absolute inset-0" />
      <div className="relative z-10 flex items-center justify-center h-full">
        <BlurText text="Welcome" delay={100} animateBy="words" />
      </div>
    </div>
  );
}
```

**Rule**: Backgrounds render first (lower z-index), text/content on top.

### Pattern 2: Scroll-Triggered Sequence

```jsx
import FadeContent from './components/FadeContent';
import ScrollReveal from './components/ScrollReveal';
import SplitText from './components/SplitText';

function Landing() {
  return (
    <>
      <section className="h-screen">
        <SplitText text="Hero Title" splitType="chars" delay={50} />
      </section>
      <FadeContent>
        <section className="h-screen">
          <ScrollReveal text="Section 1" />
        </section>
      </FadeContent>
    </>
  );
}
```

**Rule**: Stack scroll-triggered components in a single column layout. Ensure each section has enough height (`h-screen` or `min-h-screen`) for scroll triggers to fire.

### Pattern 3: Interactive Cards with Multiple Effects

```jsx
import TiltedCard from './components/TiltedCard';
import SpotlightCard from './components/SpotlightCard';
import GlareHover from './components/GlareHover';

function Gallery() {
  return (
    <TiltedCard tiltAmount={10}>
      <SpotlightCard spotlightColor="rgba(255,255,255,0.15)">
        <GlareHover>
          <img src="photo.jpg" alt="Artwork" />
        </GlareHover>
      </SpotlightCard>
    </TiltedCard>
  );
}
```

**Rule**: Nesting order matters. Outermost = structural (TiltedCard), middle = overlay (SpotlightCard), inner = surface effect (GlareHover). Not all combinations work -- test for conflicts.

### Pattern 4: Cursor Effects + Navigation

```jsx
import BlobCursor from './components/BlobCursor';
import SplashCursor from './components/SplashCursor';
import GooeyNav from './components/GooeyNav';

function App() {
  return (
    <>
      <BlobCursor />
      <main>
        <GooeyNav items={navItems} />
        {/* page content */}
      </main>
    </>
  );
}
```

**Rule**: Only ONE cursor replacement component at a time. Cursor components (`BlobCursor`, `GhostCursor`, `Crosshair`, `SplashCursor`, `TargetCursor`) are mutually exclusive.

## Scroll-Triggered Animation Patterns

### Using Motion (Framer Motion) -- Most Common

The majority of react-bits components use `motion` (the community fork of Framer Motion). Common pattern:

```jsx
// Components use `useEffect` with IntersectionObserver internally
<BlurText
  text="Hello"
  threshold={0.1}       // 10% visibility triggers animation
  rootMargin="0px"      // Trigger margin
/>
```

Key props across scroll-triggered components:
- `threshold` (0-1) -- viewport visibility percentage to trigger
- `rootMargin` -- offset from viewport edge (CSS margin syntax)
- `delay` -- stagger delay between sub-elements (ms)

### Using GSAP ScrollTrigger -- SplitText

Only `SplitText` uses GSAP ScrollTrigger:

```jsx
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
import { SplitText as GSAPSplitText } from 'gsap/SplitText';

gsap.registerPlugin(ScrollTrigger, GSAPSplitText);

// The component handles registration and cleanup internally
<SplitText
  text="Professional Animation"
  splitType="chars"       // 'chars' | 'words' | 'lines'
  from={{ opacity: 0, y: 40 }}
  to={{ opacity: 1, y: 0 }}
  duration={1.25}
  ease="power3.out"
  threshold={0.1}
  rootMargin="-100px"
/>
```

GSAP SplitText requires the premium GSAP SplitText plugin (free for GSAP club members) or the npm package `gsap/SplitText`.

## Performance Considerations

### WebGL / Three.js Components

Backgrounds that use Three.js (Aurora, Galaxy, Hyperspeed, Orb, Particles, Plasma, RippleGrid, Silk, Waves, etc.) run a WebGL render loop:

- **Single WebGL context**: Only ONE WebGL background at a time. Multiple renderers compete for GPU resources.
- **Cleanup**: Components handle `useEffect` cleanup (dispose renderer, remove canvas). If you unmount/mount rapidly, cleanup order matters.
- **Pixel ratio**: Components like Particles expose a `pixelRatio` prop. Set to `1` on mobile for performance.
- **Hyperspeed** is the most expensive (custom Three.js scene + postprocessing bloom/SMAA). Use sparingly.

### Physics Components

- **Ballpit** uses `matter-js` (2D physics engine). Limit to < 200 balls on mobile.
- **Antigravity** uses Motion spring physics. Lightweight.

### Canvas-based Components

- PixelTrail, ClickSpark, GhostCursor, PixelBlast, PixelSnow -- all use 2D Canvas
- Set `particleCount` conservatively (50-200 for smooth 60fps)
- These are lighter than WebGL but still run requestAnimationFrame loops

### Motion-based Components

- Most text animations and UI components use `motion` (spring animations)
- These are the most performant category -- they use CSS transforms/opacity
- `will-change` is set on animated elements (e.g., `will-change-[transform,filter,opacity]`)
- Layout animations (motion `layout` prop) are expensive -- used sparingly in Dock, etc.

### General Rules

1. **One WebGL background per page** -- multiple will kill performance
2. **One cursor replacement per page**
3. **Avoid animating layout properties** (width, height, top, left) -- prefer transforms
4. **Mobile**: reduce particle counts, disable WebGL effects, use CSS-only components
5. **SSR/Next.js**: most components use `useEffect` / `useRef` and need `'use client'`

## Compatibility

### With Tailwind CSS
- JS-TW and TS-TW variants are designed for Tailwind projects
- Components accept `className` prop for Tailwind class merging
- `clsx` is used internally for conditional classes
- Tailwind v4 supported (uses `@tailwindcss/vite`)

### With Other UI Libraries

| Library | Compatible? | Notes |
|---------|------------|-------|
| shadcn/ui | Yes (native) | Components install via `npx shadcn@latest add` |
| Mantine | Yes | Use CSS variants, not TW variants (Mantine uses CSS Modules) |
| NextUI | Yes | Both use Tailwind; may have class conflicts |
| animal-island-ui | Yes | react-bits animations can wrap animal-island UI cards/buttons |
| Radix Primitives | Yes (native) | Same distribution model; complementary |
| Ant Design | Partial | Different CSS methodologies; use JS-CSS variants |
| Chakra UI | Yes | react-bits uses Chakra UI internally in its docs site |

### With Frameworks
- **Next.js**: All components work; add `'use client'` directive for App Router
- **Remix**: Works; no special configuration needed
- **Vite**: Default; the library itself uses Vite
- **Astro**: Components using `window`/`document` need `client:load` directive
- **Gatsby**: Should work with standard React configuration

### React Version
- Built with React 19 (uses `useRef`, `useEffect`, `useState`, `useMemo`, `useCallback`)
- Motion (Framer Motion) requires React 18+
- Backward compatible to React 18

## react-bits vs framer-motion (Motion)

react-bits is complementary to Motion (Framer Motion), not a replacement:

| Aspect | react-bits | framer-motion |
|--------|------------|---------------|
| **Abstraction level** | Ready-made components | Low-level animation primitives |
| **Learning curve** | Low -- pick a component | Medium -- learn API concepts |
| **Customization** | Props + edit source code | Build from scratch |
| **WebGL/3D** | Built-in (Three.js, ogl) | Not included |
| **Text effects** | 23 dedicated text components | Build with `motion.span` |
| **Background generators** | 42 shader-based backgrounds | Not included |
| **When to use** | Ship fast with polished animations | Custom, one-off animated interactions |

**Recommended approach**: Use react-bits for high-level animated components (text reveals, backgrounds, card effects). Use Motion for custom layout animations, drag-and-drop, and interaction-specific motion that doesn't fit a pre-built component. They share the same `motion` library dependency.

## Common Pitfalls

1. **Double GSAP registration**: SplitText registers GSAP plugins globally. If you register them elsewhere, the `gsap.registerPlugin()` call in SplitText will be a no-op (safe), but ensure consistent GSAP versions.

2. **WebGL cleanup**: When using Three.js backgrounds with React Router, remounting may leave stale canvases. The components handle cleanup via `useEffect` return, but rapid navigation can cause glitches. Consider keeping the background mounted and swapping routes underneath.

3. **z-index stacking**: Background components render full-screen canvases. Always add `position: relative` and appropriate `z-index` to content overlaying a WebGL background.

4. **IntersectionObserver and SSR**: Scroll-triggered components use `IntersectionObserver` (browser API). In SSR frameworks, these components won't animate until client hydration. Use `next/dynamic` with `{ ssr: false }` if needed for initial load performance.

5. **Font loading**: SplitText waits for `document.fonts.ready` before animating. This prevents inaccurate measurements but can delay animation. Set `font-display: swap` on custom fonts.

6. **Tailwind version**: The Vite plugin `@tailwindcss/vite` (Tailwind v4) is used. If your project uses Tailwind v3, use CSS variants or adjust imports.

7. **Multiple motion instances**: react-bits uses `motion` (v12), not `framer-motion`. If your project already uses `framer-motion`, install `motion` alongside -- they are compatible but kept as separate packages.
