# Wabi-Neu Project — Lessons Learned

> Project: Wabi-Sabi × Neumorphism interactive scroll experience
> Stack: Vite + React 18 + TypeScript + framer-motion + Canvas 2D
> Date: 2026-05-18
> Duration: ~3 hours, 8 commits

## Issues Encountered (categorized by pipeline stage)

### 1. Brainstorming — Visual Style Selection (CRITICAL) — FIXED
**Symptom**: User couldn't perceive art styles from text descriptions. "看不出来明显的艺术风格啊" → "风格怎么这么少啊" → "没有任何显示啊，就看见16个选择条，没有详细预览啊"
**Symptom 2** (2026-05-18): Styles presented incrementally (6→4→16 across multiple rounds), text+border previews first then detailed CSS later. User had no comprehensive view for comparison.
**Root cause**: SKILL.md only listed 3 options (A/B/C) as text. 16 styles hidden behind file references. No instruction to batch-present ALL options with CSS previews.
**Applied fix** (`skills/brainstorming/SKILL.md`, `skills/bootstrap/SKILL.md`):
- Complete rewrite of Step 1 to present a **Visual Direction Catalog** in ONE message
- Part A: 3 Base Design Systems with CSS-rendered preview cards (signature CSS snippet per system)
- Part B: 16 Artistic Styles in a single matrix table (never incremental)
- Part C: 12 Font Pairings quick reference
- Part D: 8 Layout Systems quick reference
- Anti-Patterns table: explicitly forbids incremental reveal, text-only descriptions, hiding content behind file references
- Bootstrap Red Flags: added 4 new rules preventing incremental style presentation

### 2. Writing Plans — TypeScript Rigor (HIGH)
**Symptoms**:
- `verbatimModuleSyntax` enabled by Vite template → 5 files fail with "must use import type"
- `strict: true` missing → no null checks on `ctx.getContext('2d')`
- Plan created `useCanvasRenderer.ts` with `null as unknown as CanvasRenderingContext2D` (dead on arrival)
- CSS file ordering issue: `global.css` not created before component imports it

**Root cause**: Plan template has no "Vite/TypeScript gotchas" section. The executor blindly follows plan without checking tsconfig.
**Fix needed**: Add pre-flight checks to writing-plans. Add Vite+TS known gotchas to CLAUDE.md.

### 3. Subagent-Dev — Overhead for Creative Projects (MEDIUM)
**Symptom**: 54 planned subagent invocations for ~20 source files. Abandoned pure subagent execution, used hybrid.
**Root cause**: Creative projects have tight coupling (CSS tokens ↔ components ↔ canvas). Subagent isolation adds context-building overhead that exceeds implementation time.
**Fix needed**: Add project-type detection. Creative/visual projects → fewer, larger tasks. CRUD/SaaS projects → many micro-tasks.

### 4. Code Review — Canvas/Creative Coding Blind Spots (HIGH)
**Symptoms caught late**:
- Canvas `width`/`height` set every rAF frame → backing-store reallocation 60fps
- `chapterProgress` in rAF effect deps → loop restart on every scroll tick
- Module-level `let particles = []` → state leak between chapter switches
- `color.replace('rgb', 'rgba').replace(')', ...)` → fragile string manipulation

**Root cause**: Code review checklist covers React patterns but not Canvas 2D performance or creative coding patterns.
**Fix needed**: Add Canvas 2D performance checks to code-review. Add creative coding anti-patterns.

### 5. Visual Check — Missing Gate (HIGH)
**Symptom**: Text `opacity: chapterProgress` was 0 at chapter start → text invisible. Only catchable in browser.
**Root cause**: `visual-check` exists but not wired as mandatory pipeline gate. No scroll-driven animation specific checks.
**Fix needed**: Wire visual-check as mandatory post-implementation gate. Add scroll animation verification.

### 6. TDD — Canvas Testing Gap (MEDIUM)
**Symptom**: 4 chapter renderers initially untested. Added only smoke tests (11 "doesn't throw" tests).
**Root cause**: TDD patterns cover component/hook testing with RTL. Canvas 2D requires mock ctx strategy — not documented.
**Fix needed**: Add Canvas 2D testing patterns to tdd skill or knowledge base.

### 7. Content Completeness (MEDIUM)
**Symptom**: Initial implementation had empty chapters (no text/nav). User: "画面内容太少了，我需要菜单、文案信息"
**Root cause**: Pipeline treats "content" as separate from "implementation". For scroll-telling, text IS implementation.
**Fix needed**: Plan template should prompt for content requirements in creative projects.

## Optimizations Applied

### To CLAUDE.md — New Known Gotchas
1. **Vite `verbatimModuleSyntax`**: Vite React-TS template enables this by default. All type-only imports MUST use `import type`.
2. **`strict: true`**: Enable in tsconfig.app.json at scaffold time. Prevents null-unsafe patterns.
3. **Canvas 2D `width`/`height` assignment**: Destroys backing store every assignment. Use ResizeObserver.
4. **framer-motion values in rAF deps**: MotionValues in useEffect deps cause loop restart on every frame. Use refs.
5. **Module-level mutable state in renderers**: `let x = []` at module scope survives HMR but leaks between tests.

### To writing-plans/SKILL.md — New Checklist Items
1. Pre-flight: check `tsconfig.app.json` for `strict`, `verbatimModuleSyntax`
2. Creative projects: include content requirements (text, navigation)
3. Canvas projects: include HiDPI scaling, ResizeObserver sizing, error boundary
4. framer-motion + rAF: document ref-vs-state pattern

### To code-review/SKILL.md — Creative Coding Checks
1. Canvas 2D: No per-frame dimension assignment, HiDPI support, context null check
2. rAF loops: No reactive values in deps array, dt clamping, cleanup on unmount
3. Module state: No mutable module-level state in render functions
4. Color parsing: No string-replace hacks for rgb/rgba conversion

### To visual-check/SKILL.md — Scroll Experience Checks
1. Text visibility at chapter boundaries (opacity, transform)
2. Scroll-snap alignment (no cut-off elements)
3. Canvas particle behavior on chapter switch (no stutter, correct reset)
4. Mouse interaction responsiveness on canvas overlay
